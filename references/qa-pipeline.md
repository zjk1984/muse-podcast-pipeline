# TTS 预扫与音频质检

核心结论先行：**TTS 对同一文本的输出是确定性的**——同一文本＋同一音色，两次合成字节数和电平完全一致。所以预扫报出的失败在整篇生成时必现，重生成修不好，**只能改写问题行**。判定确定性失败：同行跨 run 反复失败 ＋ 直接 probe 复现 ＋ 近义改写通过。

## 预扫 5 项检查（`bin/prescan-chunks.py`）

整篇生成前逐行合成、逐行检查（已并行化，默认 6 并发）。预扫缓存 `key=sha256("voice_id|文本")[:16]`，音频存在缓存目录下的 `prescan-audio/{key}.mp3`，7 天有效；缓存直接用于后续组装——**预扫通过后不要再改脚本行文本**。

1. **截断**：合成输出只有几百字节（如 576 字节）即失败。注意"瞬态"标签是误导：内容触发的失败重试多少次都一样（如特定词被后端静默过滤、感叹号密集的句子），直接改写。二分定位法：按行切分逐段合成，quarters→halves→单句。
2. **异常安静**：某行电平比该说话人本期正常水平低 **6dB** 以上，听感接近"空白对话"。阈值由来：实测某行 -31.9dB，比该说话人中位数 -21.9dB 低 10dB，整句几乎听不见；6dB 是"明显可闻异常"的下限。
3. **时长异常**：实际时长超过期望时长的 **1.6 倍且多出 3 秒以上**，疑似 TTS 把整句循环重复合成 2–3 遍，或把句子切碎、中间插入数秒静音（"口吃"变体）。期望时长按**中英分别估算**：中文 4.5 字/秒、英文单词折 2 字、孤立字母每字母 1 字。阈值由来：直接用"字数/4.5"会高估英文行的期望时长，导致循环行从 1.8x 阈值漏网；新估算下全期 152 行验证，除真实循环行外最高仅 1.42x，1.6x 有裕量。
4. **句内长静音**：单行音频里出现 **≥2.5 秒**的静音（句首/句中/句尾），疑似 TTS 停顿注入（如 2.7 秒语音＋8.5 秒尾部数字静音）。时长和音量检查都可能漏过这种形态，只能靠逐行 `silencedetect` 拦截。
5. **多音字**（纯文本检查，不合成）：`POLYPHONES` watchlist 命中即 flag。TTS 按文本原样合成、无注音干预，误读确定性复现——**只能改写成无歧义的词**，重生成修不好。首批收录：觉字家族（睡觉/睡午觉/这觉/睡着→jiào/zháo，实测曾被误读为 jué）、表必须的"得"（děi）、一行人/行家（háng）、差不多/差点（chà）、便宜（pián）、倒闭（dǎo）、打扫（sǎo）、爱好（hào）、埋单（mái）。改写对照见 `references/writing-guide.md` "发音安全"节。

改写策略（最小改动、不改原意）：换同义词、拆短句、英文词换中文描述。程式化收尾（如"我是 XX……下期见"）可能确定性输出异常安静，换同义词绕不过时直接换完全不同的句式。

## 干声组装（`bin/assemble-dry.py`）

替代整篇二次合成：预扫已逐行合成且结果缓存，直接拼接，省一次完整 TTS 的时间和 token。

- 按 key 查预扫缓存；缺失缓存行时 exit 2，先重跑预扫补齐。
- **逐行电平补偿**：以本期行电平中位数为目标、单行 **±6dB** 封顶（解决多人音色忽高忽低；实测 4 人声 9.2dB 落差→0.2dB）。注意：不同音色对同一句中文的输出电平天然差 8dB 以上，且同一音色内部动态也可能差近 10dB——写稿端也要配合（情绪平稳、少连续感叹号）。
- 每段首尾 **8ms** `afade` 防拼接咔哒声。
- 在插入点拼入短视频原声（`/tmp/clip<N>-norm.mp3`），输出行时间线 `line-times.json` / `clip-times.json`。
- 组装前校验：脚本行数 == 音频数。

## 响度与混音

- **终混响度 -16 LUFS**：`bin/loudnorm-final.sh`，双 pass EBU R128（`linear=true` 只做静态增益），TP 目标 -2.0dB 预留 mp3 编码上冲。
- **背景音乐 ducking**：`bin/mix-episode.sh` 用 `sidechaincompress` 以干声为人声 key，有人声时 bed 自动压低约 12dB、停顿时 500ms 平滑浮起；另加 `lowpass=f=8000` 让 bed 不跟人声抢存在感。注意 threshold 是线性值（0.025≈-32dB），不是 dB。
- **音乐素材电平入库前先验**：speech -20dB、bed -35dB、独立音乐段 -30dB 左右才算正常；改素材电平要同步检查脚本里有没有反向的 `volume`。
- **换片头/片尾必须同步改 afade 时序**：`mix-episode.sh` 里 intro/outro 的 `afade` 参数是按文件时长写的（如 6 秒片头的淡出 `st=5:d=1`、5 秒片尾的淡入 `d=1.5`），换文件改时长时淡入淡出都要同步改，否则会被提前淡出切断或前几秒一直在渐强。

## 自检流程

**文本质检**（`bin/check-script.py`）：防重复段落/空白段落——删重复句、删掉或补上空话、拆长句、改全角冒号，直到"文本质检通过"。

**音频质检**（对组装出的干声 mp3，用客观检查代替耳朵）：
- **时长**：`ffprobe` 取 duration；中文 TTS 语速约每分钟 250–300 字，实际时长落在（脚本字数/300，脚本字数/200）分钟区间之外视为异常。
- **空白段**：`silencedetect=noise=-45dB:d=1.5`。长停顿的第一道防线是预扫（生成前改写）；已组装好的用 `silenceremove` 直接收紧，不要反复重生成：
  ```
  ffmpeg -hide_banner -y -i raw-backup.mp3 -af "silenceremove=start_periods=1:start_duration=0.5:start_threshold=-45dB:stop_periods=-1:stop_duration=1.0:stop_threshold=-45dB" dry.mp3
  ```
  （收紧前备份；收紧后复查无 >1.5 秒静音；正常句读停顿 <1 秒会被保留。）另记录 trim 偏移：收紧前第一段从 0 开始的静音的 `silence_end`，写入 `trim-offset.json` 供 bed 时间线对齐。
- **削波**：`astats` 看 Peak level；TTS 归一化后峰值贴近 0dB 属正常，只要不是持续削波失真就不算问题。
- 时长异常 → 回写稿改脚本、重预扫、重组装、重新自检；最多返工 2 次。2 次后仍不通过：记下问题，跳过发布环节，其余继续。**禁止用"和已发布期数横向对比"绕过检查。**

## ffmpeg 坑（实测记录）

1. `areverse` 配 `afade` 用在 1200 秒这种长音频上会输出静音（短音频没事）；循环用的 bed 不要加淡入淡出，直接稳态循环。
2. 本机 ffmpeg 的 `silenceremove` **不支持 `leave_silence` 选项**（带该选项直接报错 "Option not found"）；收紧静音用不带 `leave_silence` 的版本（见上节命令），≥1 秒的静音全删，收紧后复查即可。
3. `volumedetect` 的结果在 `-loglevel error` 下不打印——测电平别加它。
4. 自己用 `concat`/`apad` 生成的 mp3，seek 索引可能不准：output-seek（`-ss` 在 `-i` 之后）会量到错误的段落，而 input-seek（`-ss` 在 `-i` 之前）和全片解码（`silencedetect`/`atrim`）是对的。量电平分段时用 input-seek 或 atrim 交叉验证，别只信 output-seek。
5. `amix` 默认 normalize 会把每轨压约 6dB：用 `normalize=0` ＋ `alimiter=limit=0.95`。
